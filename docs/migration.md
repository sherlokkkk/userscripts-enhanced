# 迁移与恢复

原版 App Store Userscripts 的应用、容器、目录和浏览器数据不作原地修改。Debug 与 Release 也使用独立容器，不能直接共享脚本目录。当前仍有严重的脚本隔离阻塞，建议仅导入自己审查过的测试代码。

## 从原版导入

1. 在原版界面找到用户可访问的脚本目录，先完整复制到普通备份目录。保留原件。
2. 校验副本文件数量与内容；原版 GM 值不等于源码文件，不能假定复制源码便迁移了值。
3. 打开增强版管理页的 Data & Updates，选择副本中的文件，查看名称、namespace、匹配规则、grant、connect、依赖和冲突预览。
4. 明确确认后导入。源码导入默认禁用，不导入旧版扩展内部设置或原版浏览器存储。
5. 在独立测试网页验证后再启用。回退时继续使用保留的原版，不需要恢复原版容器。

宿主目录选择会拒绝已知原版容器路径和其他非空目录，避免把共享目录当作安全迁移。该防护不能识别所有人为重命名的目录；使用复制后预览的导入流程。

## 开放备份格式

Data & Updates 导出带版本号的 JSON，包含脚本源码、稳定 UUID、启用状态、增强版 GM 值及允许导出的用户设置。导入验证版本、UUID、路径、数量、大小及值结构；提交前显示冲突。源码导入与完整恢复是不同操作，源码导入保留现有值和设置。

备份不包含 Safari 授权、签名证书、原版私有存储、外部依赖缓存或系统权限。它不是包含所有离线依赖的完整磁盘镜像。Tampermonkey ZIP 格式尚未验证，不接受其为已兼容格式。

恢复会保存源码、manifest 和身份的恢复记录，检查预览时的状态版本，失败时尝试补偿；浏览器存储只补偿本次目标键，避免覆盖其他脚本的新写入。原生文件与浏览器存储之间不是 ACID 事务。回滚遇到目标已被后续编辑会拒绝覆盖；保留备份及错误详情，人工比较后重新预览。物理文件失败恢复及断电恢复尚待独立容器端到端验证。

## 更新回退

更新先下载候选、检查源码版本和权限/来源/依赖差异；确认后使用同一恢复事务应用。保留的候选与恢复记录用于手动回滚。默认不自动应用；开启自动应用后，声明发生变化的候选仍须审批。网络失败不覆盖原源码。

删除源码与 GM 值的分别选择、可撤销卸载及原版值格式迁移尚未完成，见兼容性矩阵。不要手动清除原版容器来解决导入冲突。
